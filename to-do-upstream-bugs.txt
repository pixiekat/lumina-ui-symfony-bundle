Three places the API contradicts its own documentation

Worth passing to the creator — each one fails silently:

1. The envelope key is patient_info, not the documented patientInfo. The documented key returns HTTP 200, all 367 trials, matchScore: null — a confident well-formed answer computed with no patient context. Inner keys work in either case; only the envelope is exempt from the camelCase middleware.
2. count is the page count, not the item count. itemsTotalCount is the item count. Reading count — the field every DRF client reaches for — would have shown "5 trials" instead of 88.
3. Verb asymmetry: /trials/match/ is POST-only (GET → 405), /trials/count/ is GET-only (POST → 405). Since the profile must travel in a body, counting has to go through the match endpoint.
